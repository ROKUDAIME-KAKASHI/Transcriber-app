# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope (D-14):** minimal UI only. This phase adds a share menu (popover on laptops, bottom sheet on phones), a history-aware back arrow on the meeting page, a 44px brand link, and busy/error/success states for the export buttons. Everything else stays as it is. Use only the existing tokens in `src/app/globals.css` and the primitives in `src/components/ui.tsx` (`Button`, `Panel`, `cx`, `Notice`), so the Phase 5 "Aurora Ink" restyle reaches the new UI without extra work. Do not add new color tokens, fonts, shadows or a component library.

## Spacing Scale

Declared values (must be multiples of 4). These are the existing Tailwind steps the new UI may use:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between row title and row description (`mt-1`), sheet grab-handle top margin |
| sm | 8px | Gap between export buttons (`gap-2`), Share button top margin (`mt-2`), status line top margin (`mt-2`), row vertical padding (`py-2`), icon-to-label gap (`gap-2`), popover offset from Share button (`mt-2`) |
| md | 16px | Sheet/popover inner padding (`p-4`, `px-4`), row horizontal padding (`px-4`) |
| lg | 24px | Not used in new UI |
| xl | 32px | Not used in new UI |
| 2xl | 48px | Not used in new UI |
| 3xl | 64px | Not used in new UI |

Exceptions:
- No 12px steps in new UI: share-menu rows use 8px vertical padding (`py-2`) inside the 56px row, and the status line sits 8px under the buttons (`mt-2`).
- Touch targets: every new tappable element is at least 44px tall (`min-h-11`). Share-menu rows are 56px (`min-h-14`). The brand link and back link are 44px tall (`min-h-11`).
- Bottom sheet bottom padding = 16px + `var(--safe-area-inset-bottom, env(safe-area-inset-bottom))` (use the existing `.safe-bottom` class plus `pb-4` on an inner wrapper).
- Existing panel padding (`p-5`, 20px) in the Export panel is unchanged; it is existing code, not new spacing.

## Typography

Uses the existing type tokens only (`text-meta` 13px / 20px, `text-ui` 15px / 22px). No new size is introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row descriptions, inline error/status line) | 13px (`text-meta`) | 400 | 20px (1.54) |
| Label (button labels, row titles, back link) | 15px (`text-ui`) for buttons and row titles; 13px (`text-meta`) for the back link | 600 (`font-semibold`) | 22px (1.47) / 20px |
| Heading (Export panel heading, brand "Transcriber") | 15px (`text-ui`) | 600 (`font-semibold`) | 22px (1.47) |
| Display (meeting title, existing) | 24px / 28px sm+ | 600 (`font-semibold`, existing) | 1.25 (existing) |

Rules:
- The contract uses exactly two weights: 400 (body/descriptions/status lines) and 600 (labels, buttons, row titles, back link, brand, headings).
- Implementation: change the `Button` base class in `ui.tsx` from `font-medium` to `font-semibold` (one-line change, applies app-wide so all buttons share the weight; do not stack `font-semibold` over `font-medium` via `className`, the two classes conflict). The back link changes `font-medium` to `font-semibold`.
- The share menu has no visible title (the menu's accessible name comes from `aria-label`), so it adds no heading weight.
- Nothing smaller than 13px (existing rule in `globals.css`).

3. Text selection highlight (global).

Focal point: the accent "Create minutes" / "Regenerate minutes" button is the meeting page's single focal point; "Share meeting" is deliberately secondary (neutral `variant="secondary"`) until the Phase 5 restyle.

## Component Contracts

### 1. Export panel (`ExportButtons` in `MeetingView.tsx`)

Layout is unchanged: heading row ("Export" + current name: "Minutes" / "Report" / "Transcript"), a 3-column grid of `PDF`, `Word`, `Text` buttons (`gap-2`), then a full-width `Share meeting` button (`mt-2`), then the status line (`mt-2`), then the existing Delete section.

| State | Behavior |
|-------|----------|
| Idle | Buttons show icon + label: `FileDown` PDF, `FileType` Word, `FileText` Text, `Share2` Share meeting. All `variant="secondary"`. |
| Busy (one export running) | The tapped button gets `loading` (spinner replaces its icon, label unchanged). The other three buttons are `disabled` (50% opacity) until it finishes. Only one export runs at a time. |
| Share busy | The Share button shows `loading` and its label changes to `Preparing…` while the file is built; the other export buttons are disabled. |
| Success (native share sheet opened / web download started) | No message. Buttons return to idle. |
| User cancelled the share sheet | No message (AbortError / plugin cancel is silent). |
| Error | One line under the buttons: `<p className="mt-2 text-meta text-danger" role="alert">`. Copy from the Copywriting table. Cleared when any export/share action starts. |
| Copied | One line under the buttons: `<p className="mt-2 text-meta text-success" role="status">Copied to clipboard</p>`, auto-cleared after 2500ms. |
| Old APK (plugin missing) | Error-styled line with the update hint (see copy); text is also copied to the clipboard. |
| No content | If there is no transcript and no document, all four buttons are `disabled` and the status line shows `This meeting has nothing to export yet.` in `text-muted-foreground`. |

The Share button is always rendered (the old `canShare` gate is removed, because the APK uses Capacitor Share and desktop falls back to download/copy).

### 2. Share menu (`ShareMenu.tsx`)

Opened by the Share button (`aria-haspopup="menu"`, `aria-expanded`). One component, two presentations:

| Breakpoint | Presentation |
|------------|--------------|
| `<lg` (phones, tablets, the APK) | Bottom sheet: `fixed inset-x-0 bottom-0 z-40`, `rounded-t-panel` (20px), `border-t border-border bg-card`, `.safe-bottom` + `pb-4`. Scrim `fixed inset-0 z-30 bg-black/40` covers the bottom tab bar (z-20). Grab handle: 36px x 4px `rounded-full bg-border`, centered, 8px from the top. Enter: slide up from `translate-y-full` in 200ms `ease-out`; exit 150ms `ease-in`. The global reduced-motion rule disables both. |
| `lg+` (laptops) | Popover anchored under the Share button: `absolute` in a `relative` wrapper, `mt-2`, same width as the Share button, `rounded-xl border border-border bg-card`, `z-30`, no scrim, no shadow, no animation. |

Rows (`role="menuitem"`, full-width buttons, `min-h-14 px-4 py-2`, icon 16px `text-muted-foreground` + title `text-ui font-semibold` + description `text-meta text-muted-foreground`, `hover:bg-muted active:bg-muted`, rows separated by `divide-y divide-border`):

| # | Icon | Title | Description | Shown / enabled when |
|---|------|-------|-------------|---------------------|
| 1 | `ClipboardList` | `Share minutes` (or `Share report` when the document is a Report) | `PDF file` (or `Word file` when the PDF plugin is missing in the APK) | Shown only when a document exists |
| 2 | `FileText` | `Share transcript` | `PDF file` (same fallback rule) | Shown always; disabled with description `No transcript yet` when the transcript is empty |
| 3 | `Copy` | `Copy text` | `Copies the minutes` / `Copies the report` / `Copies the transcript` (follows the current tab) | Shown always; disabled when the current tab has no text |

Phones only: below the rows, a full-width `Button variant="ghost"` labelled `Close share menu` (`mt-2`, `min-h-11`) closes the sheet.

Interaction rules:
- Tapping a row closes the menu immediately, then the action runs and the Share button shows the busy state. Errors appear in the export panel's status line, never inside the menu.
- Close on: row tap, Close share menu, scrim tap, `Escape`, Android back (via the overlay registry, D-13), and outside click on laptops.
- Focus: on open, focus moves to the first enabled row; arrow Up/Down move between rows; on close, focus returns to the Share button.
- The menu registers itself in the shared open-overlay stack on open and unregisters on close, so the Android back button closes it first (NAV-03).
- `role="menu"` with `aria-label="Share options"`. On phones, scroll lock on `body` while the sheet is open.

### 3. Back arrow on the meeting page (NAV-02)

Keep the existing header link and its look (`ArrowLeft` 16px + "Meetings", `text-meta text-muted-foreground hover:text-foreground`), with these changes:
- Weight: `font-semibold` (was `font-medium`).
- Hit area: `min-h-11` (44px), `-ml-2 px-2 rounded-lg` so the icon stays visually aligned with the title while the target grows.
- `href="/meetings"` stays (middle-click, no-JS, cold deep link). `onClick` prevents default and calls `router.back()` only when there is in-app history (same-origin `document.referrer` and `window.history.length > 1`); otherwise `router.push("/meetings")`.
- `aria-label="Back to meetings"`.
- Always visible, at the top-left of the meeting page, on every breakpoint.

### 4. Brand link (NAV-01)

`Logo` in `AppShell.tsx` stays the same visually (28px `AudioLines` tile + "Transcriber" at `text-ui font-semibold`, existing). Changes:
- `inline-flex min-h-11 items-center rounded-lg -mx-2 px-2` so the tap target is at least 44px tall in the phone top bar and the laptop sidebar.
- `href="/"`. No `aria-label` override: the accessible name stays the visible text "Transcriber", and `title="Go to Record"`.
- Works on every route including `/meetings/[id]` (it already renders in both the top bar and the sidebar).

### 5. Android back button (NAV-03), no visible UI

Order: (1) close the topmost registered overlay (share sheet); (2) if not at a root route (`/`, `/meetings`), go back with the same rule as the back arrow (history, else parent `/meetings`); (3) at a root route while recording, `App.minimizeApp()`; (4) at a root route while idle, `App.exitApp()`. No toast or confirmation dialog is shown. If the App plugin is missing, the default WebView behavior applies.

### 6. Export document styling (files, not screens; D-04)

The HTML used for the PDF (Android plugin and web print iframe) uses plain hex colors only (no `oklch()`, no CSS variables):
- Font stack: `"Noto Sans", "Noto Sans Devanagari", "Nirmala UI", Mangal, Arial, sans-serif`.
- Page A4, 18mm margins. Body 11pt, line-height 1.5, color `#111111`. H1 18pt, H2 14pt, H3 12pt, weight 600. Timestamps and meta `#666666`. Table borders 1px `#cccccc`, header cell background `#f2f2f2`, cell padding 4pt 6pt.
- Transcript export: title as H1, then one paragraph per segment: `[mm:ss]` in `#666666`, then `Speaker N:` in bold when there is more than one speaker, then the text. It covers the full transcript.
- DOCX uses the same structure: body 11pt, headings 18/14/12pt bold, complex-script font `Nirmala UI` so Devanagari renders in Word.
- Filenames: `${name}-${fileStamp()}.{txt|docx|pdf}` (existing format).

Copy rules: sentence case, no exclamation marks, every error names what failed and gives one next step. User-cancelled shares never show an error.

## Accessibility Contract

- Every new tappable element is at least 44px tall; share rows are 56px.
- Visible focus uses the existing global `:focus-visible` accent outline; do not override it.
- The error line uses `role="alert"`, the Copied line uses `role="status"`.
- Share button: `aria-haspopup="menu"` + `aria-expanded`; the menu has `role="menu"` + `aria-label="Share options"`, and the rows are `role="menuitem"`. Disabled rows use `aria-disabled="true"` and stay focusable so the reason can be read.
- Motion: sheet slide only; disabled by the existing `prefers-reduced-motion` rule.
