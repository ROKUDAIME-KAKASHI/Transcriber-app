    Create `src/lib/local/sync.ts` ("use client"-agnostic module; no top-level browser access; all state in module variables). Implement the exported API from the interfaces block.

    Snapshot store: module `snapshot` object replaced (never mutated) on change; `subscribeSync` adds to a Set of listeners; `getSyncSnapshot` returns the current object.

    Locking (D-07): `runPass()` uses an in-tab mutex (`running` flag + `rerun` flag so a poke during a pass schedules one more pass) and, inside it, `navigator.locks.request("transcriber-sync-" + userId, { ifAvailable: true }, cb)` when `navigator.locks?.request` exists (skip the pass if lock is null: another tab is syncing and will see our rows via Dexie); otherwise run directly (http LAN dev has no Web Locks).

    Triggers (D-07): `poke` schedules a pass on the next microtask/50 ms debounce; `startSync` registers `onConnectivityHint` (online -> poke with forced probe and forced pull), `document.visibilitychange` (visible -> poke + forced pull), and when `hasPlugin("App")` `App.addListener("appStateChange", s => s.isActive && poke())` (keep the handle to remove in `stopSync`). A self-rescheduling `setTimeout` loop: 5 s while `activeRecordings` (Set from `markRecording`) is non-empty, else 30 s, 60 s in needs-auth; when backing off use `max(interval, nextAttemptAt - now)`. `stopSync` clears timers/listeners and sets userId null but never touches IndexedDB (D-08).

    One pass, when `userId` is set:
    1. `if (!(await isReachable({ force }))) -> state "offline"`, stop.
    2. state "syncing". `repo.listPending(userId)`; for each meeting oldest first, skipping `syncError === "conflict"`:
       - Tombstone (deleted 1): `DELETE /api/meetings/:id`; ok or not-found -> `repo.purge`; continue (D-11).
       - `dirty.create`: POST `{ id, title, language, deviceName, engine, createdAt }`; ok (200/201) -> `applySyncResult({ clear: ["create"], savedParts: min(local.savedParts, data.savedParts ?? 0) })`; conflict -> `applySyncResult({ syncError: "conflict" })` and skip this meeting for good (Pitfall 6). Applies to native rows too (safety net, Pitfall 2).
       - Native rows (`origin === "native"`): skip tail and finish entirely (D-18; RecordingService owns them).
       - `dirty.tail` (only when create is done): `repo.getParts` -> remember `readRev`; loop `nextTailBatch(parts, savedParts, maxParts)`; PATCH `{ transcriptTail: { from, parts }, durationSec }`; ok -> `savedParts = data.savedParts` and persist it immediately via `applySyncResult({ savedParts })` (D-06); continue until `done`; then `applySyncResult({ savedParts, clear: ["tail"], readRev })` (repo only clears when localRev unchanged, Pitfall 3). conflict with numeric `savedParts` -> set cursor to it, persist, retry (max 3 per meeting per pass). too-large -> halve `maxParts` (floor 25) and retry. not-found -> `applySyncResult({ savedParts: 0, markDirty: ["create"] })` and move on (next pass re-creates).
       - `dirty.meta`: PATCH `{ title, titleUpdatedAt }`; ok -> `applySyncResult({ title: data.title ?? local.title, clear: ["meta"] })`.
       - `dirty.speakers`: PATCH `{ speakerNames }`; ok -> clear "speakers".
       - `dirty.finish` (only once tail is clear): PATCH `{ status: "DONE", durationSec }`; ok -> clear "finish".
       - Never send `document` or `template` (D-10).
       Response handling for every request goes through `classifyResponse` (fetch errors map to `null`): "auth" -> state "needs-auth", `lastError`, stop the pass, keep data (D-08); "retry" -> `markUnreachable()` when it was a network error, `attempt++`, `nextAttemptAt = now + backoffDelay(attempt)`, stop the pass; "bad-request" -> `applySyncResult({ syncError: "rejected" })` for that meeting and continue. Any ok response resets `attempt` to 0 and, if state was "needs-auth", returns to normal (D-08).
    3. Pull (after push, Pitfall 10) when forced or more than 25 s since the last pull: `since = await repo.kvGet(userId, "lastPullAt")`; GET `/api/meetings` (with `?since=` + encodeURIComponent when present, `cache: "no-store"`); ok -> `refetch = await repo.applyPull(userId, data.meetings, data.ids)`; for up to 5 refetch ids GET `/api/meetings/:id` and `repo.cacheServerMeeting(userId, { ...meeting, transcript: parsed parts })`; store `lastPullAt = new Date(Date.parse(data.serverTime) - 5000).toISOString()` (server clock only, never the device clock).
    4. state "idle", `lastSyncedAt = Date.now()`; notify pass-complete waiters.

    `flush(id, { timeoutMs = 15000 })` (D-12): loop until the deadline: run a pass immediately (ignoring backoff, forced probe), then `repo.getMeta`; return "synced" when missing or pending 0, "conflict" on syncError conflict, "needs-auth" when the snapshot is needs-auth; else wait 2 s, 4 s, 6 s... and retry; return "pending" at the deadline. Must work while another tab holds the lock (it just re-checks Dexie). `markRecording`/`isRecordingId` maintain `activeRecordings`. `PAGE_LOADED_AT = Date.now()` at module evaluation. recoverOrphans must additionally skip any RECORDING meeting whose last local write (updatedAt/lastWriteAt) is less than 30 s old, so a second tab never finalises a meeting another tab is still recording. `resumeAuth()` clears needs-auth and pokes.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Information disclosure | Uploading user A's DB under user B's session | mitigate | Engine bound to the effective userId; authenticated session id always overrides lastUserId, which switches DBs; the server additionally scopes by session userId and 409s foreign ids |
| T-02-13 | Denial of service | Retry storms against Vercel/Neon | mitigate | `backoffDelay` exponential with 60 s cap + jitter; one loop per user via Web Locks; 409 loops capped at 3 per pass; conflict rows stop retrying |
| T-02-14 | Repudiation / data loss | 401 or sign-out wiping unsynced meetings | mitigate | needs-auth only pauses; no IndexedDB deletion outside `purge` after a confirmed DELETE |
| T-02-15 | Tampering | Device overwriting AI minutes | mitigate | Request bodies never include document/template (acceptance check) |
</threat_model>
