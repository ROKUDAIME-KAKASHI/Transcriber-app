# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** small UI only (03-CONTEXT D-14..D-20; Aurora Ink restyle is Phase 5). Adds: Offline pill + explainer, disabled-with-reason gating for Cloud engine and AI minutes, "Download for offline" model control with status, "Update ready" notice, AuthGate skeleton and "Sign in needs internet once" state, offline `/login` message, "Not on this device yet" meeting state, and honest screen-on copy. Use only existing tokens in `src/app/globals.css` and primitives in `src/components/ui.tsx` (`Button`, `Panel`, `Badge`, `Notice`, `OptionList`, `cx`). No new colors, fonts, shadows or libraries. Phase 5 restyles through the same primitives.

## Component Contracts

### 1. ConnectivityPill (D-13, D-14)

- Rendered in `AppShell`: phone top bar (right side, before any existing actions) and laptop sidebar (below the brand). Rendered only when `useConnectivity()` is `offline`. Hidden for `online` and `unknown`.
- Look: `inline-flex h-7 items-center gap-1 rounded-full bg-muted px-2 text-meta font-semibold text-muted-foreground`, icon `WifiOff` 14px in `text-warning`, label `Offline`. It is a `button` (`aria-expanded`, `aria-controls`) with the 44px hit area described above.
- `role="status"` + `aria-live="polite"` on a wrapper that stays mounted (empty when online) so screen readers announce the appear/disappear. Announced text: `Offline` on change to offline, `Back online` on change to online (visually hidden `sr-only` span; no visible "Back online" toast).
- Appear/disappear: plain mount/unmount, no animation. A 150ms `opacity` fade (`transition-opacity`) is allowed; reduced motion disables it globally.
- Tap/click opens the explainer: popover (lg+: `absolute`, `mt-2`, `w-72`, `rounded-xl border border-border bg-card p-4`, `z-30`; phones: same card anchored under the top bar with `fixed inset-x-4 top-[calc(3.5rem+env(safe-area-inset-top))]`). No scrim. Close on: outside tap, `Escape`, tapping the pill again, Android back (register in the existing open-overlay stack from Phase 1). Focus returns to the pill on close.
- Explainer content (`text-meta`, `role="dialog"` `aria-label="Offline help"`): a title line `You're offline` (`text-ui font-semibold`), then two short lists with `Check` (`text-success`) and `X` (`text-muted-foreground`) 16px icons:
  - Works: `Record on-device`, `Read saved meetings`, `Export and share saved meetings`
  - Needs internet: `Cloud recording with speaker labels`, `Creating minutes with AI`
  - Footer line: `Everything you record is saved on this device and syncs when you're back online.`

### 2. Feature gating (D-15, D-16, D-17)

Reason line component (`GateReason`): `<p className="mt-2 text-meta text-muted-foreground">` directly under (or beside on lg+) the disabled control, with `Info`/`WifiOff` 14px icon optional. Disabled control gets `disabled` + `aria-disabled="true"` + `aria-describedby` pointing at the reason line. Reasons: `Needs internet` (offline) or `Sign in again to use this` (signed out). When the gate flips to enabled the reason line unmounts and the control re-enables with no reload and no toast.

Record screen, Cloud engine option (OptionList item):
- Offline: item rendered disabled; its description line is replaced by `Needs internet`.
- If saved engine is Cloud and offline: the effective engine for the session is the on-device engine (preferred model). Show a neutral note above Start: `<Notice tone="neutral" icon={<WifiOff/>}>` text `Offline, using on-device. Your Cloud choice comes back when you're online.` The saved preference is not changed. When online and idle again the note unmounts and Cloud is selected again.
- Recording in progress: no UI change at all when connectivity flips. No note, no disable.

Meeting page AI minutes (`Create minutes` / `Regenerate minutes`, plus any other AI entry):
- Offline: button `disabled`; reason `Needs internet` in the line right under it. Existing minutes, report and transcript remain fully readable.
- Signed out/unauthorized: reason `Sign in again to use this`.
- Online again: re-enabled automatically; keep accent styling only when enabled.

### 3. Honest on-device offline copy (D-18)

On the Record screen, reuse the existing battery/screen-on note pattern (`Notice tone="neutral"`, same position). Content is engine-specific:
- On-device engine selected: title `Keep the screen on`, body `On-device recording works with no internet, but it stops if the screen locks. Keep this screen open while you record.`
- Cloud engine selected (online): body `Cloud keeps recording with the screen off, but it needs internet the whole time.`
Do not claim locked-screen offline recording anywhere.

### 4. OfflineModelControl (D-19, D-20, D-21)

Placed on the Record screen below the engine selector, shown only when an on-device engine is selected. Layout: a `Panel` (`p-4`) with a title row, a status row, an optional progress bar, a size/reason line, and a button row.

- Title: `Offline use` (`text-ui font-semibold`) with a status `Badge` at the right. Subtitle (`text-meta text-muted-foreground`): `<engine name> + backup model` and size, for example `Moonshine Base + Tiny, about 90 MB`. Size comes from `MODELS[...].sizeMb`, summed and rounded to nearest 5 MB, prefixed `about`.
- States:

| State | Badge | Body | Button(s) |
|-------|-------|------|-----------|
| Not downloaded (online) | `Badge tone="neutral"` `Not downloaded` | `Download once to record with no internet. Uses about 90 MB. Wi-Fi recommended.` | `Download for offline` (`variant="secondary"`, `Download` icon, `min-h-11`) |
| Not downloaded (offline) | `neutral` `Not downloaded` | `Not ready offline. Download needs internet.` | Button `disabled`, reason line shown |
| Downloading | `Badge tone="neutral"` `Downloading 42%` (only the progress fill carries the accent) | Progress bar: `h-1 rounded-full bg-muted` track, `bg-accent` fill, `role="progressbar"` `aria-valuenow` `aria-valuemin=0` `aria-valuemax=100` `aria-label="Offline model download"`. Under it (`text-meta`): `Keep this screen open until it finishes.` | `Cancel download` (`variant="ghost"`) |
| Ready | `Badge tone="success"` `Ready offline` (`Check` 14px) | `Works with no internet.` | none (a quiet `Remove` is out of scope) |
| Error | `Badge tone="live"`-style danger `Download failed` | `<p className="text-meta text-danger" role="alert">Couldn't finish the download. Check your connection and try again.</p>` | `Try again` (`variant="secondary"`) |
| Cancelled / partial | `neutral` `Not downloaded` | `Download paused. Resuming skips what is already saved.` | `Download for offline` |

- Percent updates at most every 250ms; badge text is `aria-live="off"`; a `sr-only` `role="status"` announces `Download started`, `Ready offline`, or `Download failed` once per transition.
- First tap on mobile data: no extra modal. The size and `Wi-Fi recommended` text in the body is the warning.
- Readiness is derived from Cache Storage (D-20); the UI only renders the resulting state. On entering `Ready` call `navigator.storage.persist()` silently.
- Start button gate: if the selected engine is not ready AND offline, Start is `disabled` with reason `Not ready offline. Download needs internet.` below it (`GateReason`). If online, Start behaves as today (downloads on first use, D-21).
- Per-engine status also appears as a one-word suffix in the engine OptionList description when known: `Ready offline` (success color text only for that suffix) or nothing.

### 5. UpdateNotice (D-06)

- Shown only when a new SW is waiting. A `Notice tone="neutral"` card, `fixed` as specified in Spacing exceptions, `role="status"`.
- Title `Update ready`. Body:
  - Idle: `Reload to get the latest version.` Button `Reload to update` (`variant="primary"`, `min-h-11`) and `Later` (`variant="ghost"`).
  - Recording (flag set): body `It will install the next time you open the app.` No buttons except `Dismiss` (`variant="ghost"`). The primary button is never shown while recording and the page is never reloaded.
- `Later`/`Dismiss` hides the notice until the next app launch or the next time the SW state changes.
- Chunk-load failure while recording: same card, title `Update needed`, body `Part of the app couldn't load. Finish recording, then reload.` While idle: one guarded automatic reload, no UI.

### 6. AuthGate (D-11, D-12)

- Loading skeleton: renders the app frame outline so there is no layout jump: on phones a top bar placeholder and tab bar placeholder, on lg+ a sidebar placeholder, plus three content blocks (`bg-muted rounded-panel h-24`, `animate-pulse`, gap `gap-4`). `aria-busy="true"`, `role="status"` with `sr-only` text `Loading`. Max visible duration is bounded by the session check; after 6 seconds of loading and unreachable, fall through to the rules in D-11. Reduced motion stops the pulse (global rule).
- Signed in or cached user while offline: renders the app normally. No extra message beyond the pill.
- Needs internet once (no cached user, offline): centered `Panel` (`max-w-sm p-6 text-center`) on the page background: `WifiOff` 24px `text-muted-foreground`, heading `Sign in needs internet once` (`text-ui font-semibold`), body `Connect to the internet, then sign in. After that the app works offline.` (`text-meta text-muted-foreground`), button `Try again` (`variant="secondary"`, `min-h-11`, `loading` while the probe runs). On success it proceeds automatically when the health probe passes.
- Unreachable server but not offline (probe failing, `unknown` persistent): same panel, copy unchanged.
- Server reachable and unauthenticated: redirect to `/login` with no flash of app content.
- `/login` offline: the form stays visible. The submit button is `disabled` and a line under it (`text-meta text-muted-foreground`, `role="status"`) reads `You're offline. Sign in needs internet.` On online it re-enables automatically. If a submit fails with a network error: `Couldn't reach the server. Check your connection and try again.` in `text-danger` `role="alert"`.

### 7. Meeting not on this device (D-09)

When the Dexie record is absent, the server is unreachable: centered Panel with `FileX` 24px, heading `Not on this device yet` (`text-ui font-semibold`), body `Open this meeting once while online to keep a copy here.`, button `Back to meetings` (`variant="secondary"`, `min-h-11`, goes to `/meetings`). While loading (record absent but reachable): the same skeleton blocks as AuthGate. Fetch failure while online: `Couldn't load this meeting. Try again.` plus `Try again` button.

### 8. SW fallback and APK error page (D-05, D-07)

- `/offline` page (rendered by the SW for unknown paths): same Panel style as 6, heading `You're offline`, body `This page isn't saved on this device. Go back to Record or your meetings.`, two buttons `Open Record` (`variant="secondary"`) and `Open meetings` (`variant="ghost"`).
- `mobile/www/index.html` (APK errorPath, first-ever launch offline): heading `Can't open the app`, body `Open the app once with internet to set up offline use.`, button `Try again`. Uses existing plain-CSS neutral styling from the file; no new look.

## Accessibility Contract

- All new tappable elements are at least 44px tall (`min-h-11`), including the pill hit area.
- The pill's live region is always mounted; the progress bar has `role="progressbar"` with values; the gate reasons are linked with `aria-describedby`; disabled controls use `aria-disabled="true"` and remain focusable so the reason is reachable.
- The Update notice is `role="status"` (non-interruptive); the download error and login network error use `role="alert"`.
- Focus: popover close returns focus to the pill; AuthGate and the skeleton never trap focus.
- Offline state is never conveyed by color alone (icon + the text `Offline`).
- Motion: only `animate-pulse` on the skeleton and an optional 150ms fade; both fall under the global `prefers-reduced-motion` rule.
- Contrast: all text uses existing token pairs (`text-muted-foreground` on `bg-card`/`bg-muted` already meets AA in both themes); the `--warning` icon is decorative.
