# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** small UI only (04-CONTEXT D-06, D-07, D-10, D-11, D-12). Adds: tappable speaker chips in `TranscriptView`, a rename-speaker sheet (phone) / popover (lg+), a subtle "Identifying speakers" and "Refining speakers" status line, the diarization model counted in the `OfflineModelControl` size label, and speaker names flowing into exports and AI minutes (no new UI there). Aurora Ink restyle is Phase 5 and goes through the same primitives. Use only existing tokens in `src/app/globals.css` and primitives in `src/components/ui.tsx` (`Button`, `Panel`, `Badge`, `Notice`, `GateReason`, `cx`). No new colors, fonts, shadows or dependencies. Sources: Pre-populated from 04-CONTEXT.md and the Phase 3 UI-SPEC; the remaining choices are recommended defaults.

Exceptions:
- Speaker chip is a tap target: visible chip `h-7` (28px); hit area is `min-h-11` (44px) via `-my-2 py-2` on the button wrapper so the transcript grid's row rhythm (`space-y-5`) does not change. Sheet buttons (`Save name`, `Discard changes`) and the name input are `min-h-11`.
- Phone sheet is `fixed inset-x-0 bottom-0` with `pb-[calc(1rem+var(--safe-area-inset-bottom,env(safe-area-inset-bottom)))]` so it clears the gesture bar and sits above the bottom tab bar (z above tab bar: `z-40`). It never changes the page height.
- Dots in the chip and status line are 8px (`h-2 w-2`) (the existing `TypingDots` component is reused unchanged), decorative, as already in the codebase.

Accent reserved for:
1. `Save name` button in the rename sheet (`Button variant="primary"`, the single primary in the sheet).
2. Keyboard focus ring (global `:focus-visible`) including on the chip and the name input.
3. Existing items unchanged (live caret in the transcript, "Show more paragraphs" link, Start CTA).

Rules:
- Speaker identity is conveyed by dot color AND label text (`Speaker 2` / the custom name), never by color alone. Speaker 0 shares `--accent`'s hue; that is existing and accepted, but accent-as-action is not implied for the chip: the chip has no underline or accent fill.
- Status lines are neutral (`text-muted-foreground`); identifying/refining is informational, never warning or error.
- Chip contrast: label text uses the speaker color on `--background`/`--card`; these are the existing values and not changed here. The name itself is also in the speaker color, with the dot supplying redundancy.

## Component Contracts

### 1. Speaker chip (D-07, D-10, D-11)

- Replaces the static `<span>` at `TranscriptView.tsx` lines 95-100. Still rendered only when the meeting has more than one distinct speaker and the speaker changed from the previous paragraph (existing `showSpeaker` logic unchanged). A one-speaker meeting shows no chips and no rename entry point.
- Element: `<button type="button">` with `inline-flex h-7 items-center gap-2 rounded-full px-2 text-meta font-semibold hover:bg-muted active:bg-muted`, 44px hit area per Spacing exceptions, `transition-colors` 150ms. Dot `h-2 w-2 rounded-full` in `speakerColor(n)`. Label text color `speakerColor(n)`.
- Label text: `speakerLabel(n, speakerNames)`, i.e. the custom name or `Speaker {n+1}`. Truncate with `max-w-[12rem] truncate` and a `title` attribute with the full name.
- Affordance: a trailing `Pencil` icon 12px is NOT shown by default (keeps the transcript calm). Hover/focus on lg+ reveals a `Pencil` 12px at `opacity-0 group-hover:opacity-100 group-focus-visible:opacity-100`. On phones the chip is tappable without a visible cue; discoverability is covered by a one-time hint (see 3). `aria-label="Rename {label}"`, `aria-haspopup="dialog"`, `aria-expanded` bound to the open state.
- Read-only contexts: while a recording is in progress the chip is still tappable (rename applies to the live view and to the meeting when saved). Deepgram meetings use the same chip and sheet. No change to cloud behaviour.
- Live behaviour: a phrase labelled live may be relabelled by the stop-time refinement. The chip text updates in place with no animation beyond the normal re-render; no toast, no flash.

### 2. Rename sheet / popover (D-10, D-11)

- Opened by tapping a chip; one open at a time. Phones (below `lg`): bottom sheet `fixed inset-x-0 bottom-0 z-40 rounded-t-panel border border-border bg-card p-4`, with a scrim `fixed inset-0 z-30 bg-foreground/30` (tap closes). lg+: popover anchored under the chip, `absolute z-30 mt-2 w-72 rounded-xl border border-border bg-card p-4`, no scrim.
- Content (`role="dialog"` `aria-modal="true"` on phones, `aria-label="Rename speaker"`):
  - Title row: `Rename speaker` (`text-ui font-semibold`) with the current speaker dot (8px, speaker color) before it.
  - Field: `FieldLabel` `Name` + text input (`inputCls`, `min-h-11`, `maxLength=40`, `autoComplete="off"`, `autoCapitalize="words"`, `enterKeyHint="done"`), prefilled with the current custom name or empty with placeholder `Speaker {n+1}`. Autofocus on open (lg+ only; on phones focus the input but do not force the keyboard if the sheet opened by long scroll; simple rule: focus on open for both, the sheet repositions above the keyboard via `visualViewport` bottom padding).
  - Helper (`text-meta text-muted-foreground`): `Applies to the transcript, exports and minutes.`
  - Buttons row (`flex justify-end gap-2`): `Discard changes` (`variant="ghost"`, `min-h-11`) and `Save name` (`variant="primary"`, `min-h-11`).
- Behaviour:
  - `Save name` (or Enter) trims the name; an empty or whitespace-only value clears the custom name (reverts to `Speaker N`) and still closes. A name equal to another speaker's name is allowed (no error).
  - Saving writes `speakerNames["{n}"]` in Dexie, marks `meta`/`speakers` dirty, and closes. The chip, every other chip for that speaker, TXT/Word/PDF exports and the minutes transcript text pick up the name immediately (D-10). No toast; the chip updating is the confirmation.
  - If the name exceeds 40 characters the input blocks further typing; no error copy is needed. If the save fails (Dexie write error): inline `<p className="text-meta text-danger" role="alert">Couldn't save the name. Try again.</p>` above the buttons and the sheet stays open.
  - Offline is irrelevant: writes are local and sync later. The sheet has no gating and no `Needs internet` reason.
- Close paths: `Discard changes`, scrim tap (phones), outside tap (lg+), `Escape`, Android back, swipe-down is out of scope. Register with `pushOverlay(close)` on open and call the returned cleanup on close (also on unmount) so the Android back key (via `closeTopOverlay`) closes the sheet before navigating. Closing without saving discards edits. Focus returns to the chip that opened it.
- Motion: sheet enters with a 150ms `opacity` + `translate-y-2` to 0 (`transition`), exits instantly; popover fades 150ms. Reduced motion disables both via the global rule.

### 3. Discoverability hint (one-time)

- The first time a transcript with 2+ speakers renders on a device, show a single `text-meta text-muted-foreground` line directly above the transcript: `Tap a speaker's name to rename it.` with an `Info` 14px icon, `role="status"`. Dismissed permanently after the first rename or by the `X` icon button (`aria-label="Dismiss hint"`, 44px hit area); persisted in `localStorage` key `speakerRenameHintSeen`. Not shown while recording, not shown on one-speaker meetings, not shown in exports.

### 4. Identifying / refining status (D-04, D-08, SPK-05)

A single non-interactive line, never a banner, never blocking:

| State | Where | Text | Visual |
|-------|-------|------|--------|
| Live, labels being computed (recording, on-device engine, embedding model ready, at least one phrase pending embedding) | Under the last paragraph in the existing "Now" row region, or beside the recording status text in the Recorder panel | `Identifying speakers` | `TypingDots` (existing 3 pulsing dots) before the text. Shown only while there is a pending embedding job; hidden when the queue is empty so it does not flicker (hold at least 1s once shown). |
| Skipped (backlog high / slow device, D-04) | Same slot | `Catching up on transcription first, speakers will follow` | Static, no dots. Shown only if embeddings are being skipped; replaces the line above. Never in red. |
| Refining after stop (D-08) | Meeting page header meta area or under the title, while the re-cluster runs | `Refining speakers` | Single 14px `Loader2` spinning icon (`animate-spin`, `motion-reduce:animate-none`) before the text; auto-dismiss when finished. If it takes under ~300ms it is never shown (delay the mount by 300ms). |
| Done | Nothing | none | The labels simply update. No success toast, no "Speakers identified" message. |
| Embedding model missing offline (D-02, D-13) | Nothing | none | Recording proceeds and no labels appear; no error. The Offline-use control status (see 5) is the only place this is surfaced. |
| Diarization failure (any) | Nothing | none | Silent (D-13); labels stay as they were. |

- Typography: `text-meta text-muted-foreground`. `aria-live="off"` on the line (it flickers); one `sr-only role="status"` announcement `Refining speakers` on start and `Speakers updated` on finish for the post-stop pass only.
- Existing `Catching up · N phrases waiting` line for transcription backlog is unchanged and takes visual priority: when it is shown, the diarization line is suppressed (only one status line at a time under the live row).
- Placement must not shift the transcript: the line occupies an already-reserved row under the live text or sits in the header meta and does not change header height (use `min-h-5` reserved row on the meeting page while refining).

### 5. OfflineModelControl size label (D-02)

- No new control, state or button. The diarization embedding model is part of the on-device chain, so for every on-device engine the existing subtitle and body sum include it: `Moonshine Base + Tiny, about 90 MB` becomes `Moonshine Base + Tiny + speaker model, about 95 MB` (size = `totalSizeMb(chain)` including the ~6.7 MB model, rounded to nearest 5 MB, prefixed `about`, per Phase 3 rules).
- Subtitle naming: append `+ speaker model` as the last item of the chain list. Body copy (not downloaded): `Download once to record with no internet. Uses about {N} MB. Wi-Fi recommended.` with N from the new total.
- Status and readiness: `Ready offline` requires the ASR chain only (recording must never be blocked by the speaker model, D-02). If ASR is cached but the speaker model is not, the badge stays `Ready offline` and the body adds one line (`text-meta text-muted-foreground`): `Speaker labels need the speaker model. Download it to label speakers offline.` with `Download for offline` available (`variant="secondary"`) that fetches only what is missing; resuming skips what is saved (Phase 3 behaviour). After download this line unmounts.
- Progress, error and cancelled states are the Phase 3 contract unchanged; percent covers the whole chain including the speaker model.
- Deepgram engine selected: control is hidden as today; no speaker-model mention.

### 6. Exports and AI minutes (D-10, D-12): no new UI

- Everything uses `speakerLabel(n, speakerNames)`: TXT (`transcriptToText`), Word, HTML/PDF and the transcript text sent to minutes. The format of a labelled line is `{Name}: {text}` in TXT and the minutes input, a bold name in Word/PDF; multi-speaker meetings only (single speaker meetings export with no labels, as today).
- No dialog or option is added to export or minutes. The minutes prompt text change (D-12) is not user-visible.
- Meeting page `Create minutes` button gating and copy from Phase 3 are unchanged.

## Accessibility Contract

- Chip is a real `button` with a 44px hit area, visible focus ring, `aria-label="Rename {label}"`, `aria-haspopup="dialog"`, `aria-expanded`.
- Rename sheet: `role="dialog"`, `aria-label`, focus moved to the input on open, focus returns to the chip on close, focus is contained inside the sheet while open on phones (`aria-modal`), Enter saves, Escape cancels.
- Speaker identity never relies on color: dot plus text label on every paragraph run.
- `role="log"` `aria-live="polite"` on the transcript stays as is; chip relabelling after refinement is not announced per phrase (single `Speakers updated` status after the post-stop pass only).
- Status line: `aria-live="off"` to avoid chatter; one polite `sr-only` announcement for the post-stop pass.
- Motion: only `animate-pulse` dots, `animate-spin` on `Loader2`, 150ms sheet/popover fade, 150ms chip hover color; all disabled under the global `prefers-reduced-motion` rule (`animate-spin` gets `motion-reduce:animate-none`).
- Tap targets 44px; text at least 13px; contrast uses existing token pairs (speaker colors already tuned per theme in `globals.css`).

## Notes for planner/executor

- Visual anchor: the transcript text is the anchor; chips and status lines stay subordinate. In the rename sheet the `Save name` button is the primary anchor.
- Defaults chosen without user input (recommended): theta and thresholds are not a UI concern; hint persistence key, 40-char limit, 300ms refine delay and 1s hold on the status line are tunable constants.
- `speakerLabel` must be the only place producing `Speaker N` strings (TranscriptView currently hard-codes it at line 98).
