# 08-03: Recorder integration (native local capture driven by useRecorder)
Objective: in the APK, an on-device (Moonshine/Whisper) recording starts the native `mode: "local"` capture and the page transcribes it through a feed-mode VoiceChunker, with a committed cursor stored atomically with the parts. Website and old APKs keep today's getUserMedia path.
Tasks:
1) Dexie fields (no schema bump, not indexed): `LocalMeeting.nativeCapture?: 0|1`, `nativeCursor?: number`; `NewLocalMeeting.nativeCapture?`; `createLocal` sets them; `putParts(..., extra?: { nativeCursor?, finishNative? })` writes the cursor (monotonic) in the same transaction as the parts; `recoverOrphans` skips `nativeCapture === 1`.
2) `VoiceChunker.onSegment` gets a 4th argument (first sample of the phrase incl. preroll) so in-flight phrases can hold the cursor back exactly.
3) `useRecorder`: capability gate (`nativeCapabilities().localCapture` and a device store) then `startNative`: create local row, load model, `MeetingRecorder.start({mode:"local"})`, pump loop (readAudio -> frameBlock -> chunker.feed, catch-up pacing by worker promises + embedding drain, batch embeddings, previews off while behind), 500 ms native tick (seconds, level, pause state, stopped-by-itself), cursor persisted with every `putParts` and `releaseAudio` only after it resolves, native pause/resume/stop, stop drains to `ended` then flush, await finals, refine, DONE.
4) Detach (unmount) keeps capture running and persists a final cursor; a module-level barrier makes the next mount wait for it. Mount resumes an active capture via `listCaptures()` (never `start()`), rebuilding parts, embeddings and the online speaker state.
5) `useNativeRecorder.apply` ignores `mode === "local"`; `Recorder.tsx` picks the local path (copy, battery banner, mic field) when capable.
6) Pure helpers + tests (`nativeSession.ts`).
Verify: `npx tsc --noEmit`, `npm test`, `npm run build`. Done: all green; old APK/website path untouched.
