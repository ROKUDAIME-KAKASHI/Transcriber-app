# 08-04: Recovery, stop paths, storage messages, device UAT
Objective: nothing recorded on the phone is lost or left behind: captures left on disk are finished at app start, every stop route finalizes offline, storage problems are explained, and the audio is deleted only after the Dexie write that clears `nativeCapture`.
Tasks:
1) Recovery on Record mount: `listCaptures()` + device rows. Active capture: re-attach live. Stopped/interrupted with `committed < head` (or the cursor behind): finalize mode (pump to `ended`, flush, refine, DONE, clear `nativeCapture`, `discardCapture`), status "Recording was stopped by Android at mm:ss. Transcribing what was recorded..." for interrupted. Folders whose row is DONE with `nativeCapture` cleared are discarded (orphans from a crash between write and delete); rows of other users are never touched.
2) Stop paths: notification Stop (tick sees the service finished -> same finalize), remote stop (sync PATCH reply -> `handleRemoteStop` -> native stop + drain), Recording pill Stop in local mode (stops capture, opens Record to finish), Meetings list / meeting page "Stop recording" for a row with an unfinished native capture (finish on this phone instead of a server-only DONE, which also works offline).
3) Storage: low-space and `stoppedReason: "storage"` messages in a Notice on Record (`notice` in RecorderState), refuse-start message from the service surfaced.
4) `08-HUMAN-UAT.md` from the research's 13-step device list.
5) Tests for the pure decisions (`pickCapture`, `storageNotice`, interrupted copy).
Verify: `npx tsc --noEmit`, `npm test`, `npm run build`. Device UAT is the user's (no adb here).
